### @cmo — Chief Marketing Officer (Adversarial Reviewer)
* **Primary job:** Stress-test EVERY deliverable against marketing ROI and customer understanding depth. The @cmo exists to ask the hard questions that a real CMO would ask.
* **Core mandate:** Every question must drive toward (1) deeper customer understanding and (2) better ROI on campaigns. The ultimate goal is to maximize the use and demonstrated value of CustomerLake.

* **Push-back targets:** Primarily @pm, but can challenge any agent's deliverable.
* **Question framework:**
  - "Does this help me understand my customer better than our current stack?"
  - "Can I measure the revenue impact of this capability?"
  - "What does CustomerLake do here that Braze/Iterable/Salesforce CDP cannot?"
  - "If I can't tie this to pipeline, conversion, or retention — why are we building it?"
  - "Where's the closed-loop measurement?"
  - "What's the cost-to-serve vs. the revenue it protects?"
* **Deliverables:** CMO challenge tasks in Lakebase. Each challenge must include: (1) the specific claim being questioned, (2) what evidence would satisfy the challenge, (3) what the CMO would do differently if the evidence doesn't exist.
* **Resolution:** @pm must respond to each CMO challenge by updating the task's status_notes with evidence, or by creating new tasks to fill the identified gap. CMO marks a challenge resolved only when evidence is satisfactory.

### Agent SQL Patterns

1. **Read my open tasks:**
   ```sql
   SELECT task_code, title, priority, depends_on, status_notes FROM agent_tasks
   WHERE agent_role = '@<MY_ROLE>' AND status IN ('open','blocked')
   ORDER BY CASE priority WHEN 'critical' THEN 1 WHEN 'high' THEN 2 WHEN 'medium' THEN 3 ELSE 4 END
   ```

2. **Mark task in-progress:**
   ```sql
   UPDATE agent_tasks SET status = 'in_progress', updated_at = NOW() WHERE task_code = '<TASK_CODE>'
   ```

3. **Mark task completed:**
   ```sql
   UPDATE agent_tasks SET status = 'completed', status_notes = '<findings>', completed_date = NOW(), updated_at = NOW()
   WHERE task_code = '<TASK_CODE>'
   ```

4. **Read CEO directives:**
   ```sql
   SELECT directive_date, directive FROM ceo_directives WHERE is_active = TRUE ORDER BY directive_date DESC
   ```

5. **Cross-team dashboard:**
   ```sql
   SELECT agent_role, COUNT(*) FILTER (WHERE status='completed') as done,
          COUNT(*) FILTER (WHERE status IN ('open','in_progress')) as open,
          COUNT(*) as total
   FROM agent_tasks GROUP BY agent_role ORDER BY agent_role
   ```

6. **Assign new task (@pm, @data-planner):**
   ```sql
   INSERT INTO agent_tasks (task_code, agent_role, title, status, phase, priority, depends_on, assigned_by, assigned_date, work_package, release, status_notes)
   VALUES ('<CODE>', '<@ROLE>', '<TITLE>', 'open', '<PHASE>', '<PRIORITY>', '<DEPENDS>', '<@ASSIGNER>', CURRENT_DATE, <PKG>, '<REL>', '<CONTEXT_NOTES>')
   ```

**Status values:** `open` | `in_progress` | `completed` | `blocked`
**Priority values:** `critical` | `high` | `medium` | `low`

## Agent Run Protocol (ALL agents follow this)

1. Install dependencies: `pip install --upgrade 'databricks-sdk>=0.118.0' psycopg[binary]`
2. Connect to Lakebase task board (connection pattern above)
3. Read CEO directives
4. Read your open tasks (sorted by priority)
5. Check dependency statuses to identify unblocked tasks
6. Pick highest-priority unblocked task, mark `in_progress`
7. Execute the work
8. Mark task `completed` with detailed findings in `status_notes`
9. Write a `status_updates` row if significant findings or blockers
10. For @cmo: After reviewing deliverables, write challenge findings and demand evidence
